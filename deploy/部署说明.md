# 部署说明（移植到另一台 UNO Q）

这个包是 App 的**完整源码**：MCU 固件、ROS 2 节点与参数、网页前端、地图。
目标板上不需要任何本机残留（没有预置镜像 tag、没有本地路径依赖），
唯一要准备的是三个外部镜像和固件平台 —— `deploy/prepare.sh` 负责前者，
App Lab 负责后者。

```
uno-q-ros2-demo_20261124/
├── app.yaml            App Lab 清单（端口 7000，bricks：web_ui / ros2_bridge / object_detection）
├── sketch/             MCU 固件（arduino:zephyr 1.1.0 + RouterBridge 0.4.4）
├── python/             底盘控制、摄像头、检测、导航命令队列
├── assets/             网页（地图、摇杆、摄像头、检测框）
├── bricks/ros2_bridge/ ROS 2 容器源码 + Dockerfile + 地图
├── docs/  README.md
└── deploy/             ← 只在包里，不参与运行，拷进板子后可以删
```

## 一、两个压缩包怎么选

`程序/` 目录下同一天有两种包，内容一样，只是打包方式不同：

| 文件 | 怎么用 |
|---|---|
| `uno-q-ros2-demo_20261124.app.zip` | **App Lab 官方导出**。目标板执行 `arduino-app-cli app import` 直接导入，最省事 |
| `uno-q-ros2-demo_20261124.zip` | 源码快照（根目录是 `uno-q-ros2-demo_20261124/`）。手动拷到 `~/ArduinoApps/`，或用来阅读/比对代码 |

两者都带 `deploy/`，所以准备镜像的脚本在哪个包里都有。

## 二、前置条件

| 项目 | 要求 | 说明 |
|---|---|---|
| 硬件 | UNO Q（4 GB 内存版） | 摄像头、雷达、底盘按原理图接好 |
| 系统 | 出厂系统 + `arduino-app-cli` | 本包在 App Lab **0.12.x** 上验证 |
| 磁盘 | 镜像存储目录 **≥ 8 GB 可用** | 三个镜像 5.6 GB + 构建缓存 1~2 GB |
| 网络 | 能访问镜像站 | 直连 ghcr.io / Docker Hub 在国内容易超时，脚本已内置镜像站 |
| 内存 | 3.6 GB 可用 | 跑起来后 ros2 容器约 2.4 GB，别在板上再开 ros2 CLI 节点 |

> 磁盘不够是最常见的"移植失败"：`docker build` 到最后一步报
> `no space left on device`。`prepare.sh` 开头会检查并打印迁移 docker 数据
> 目录的命令（本机就是把 `data-root` 挪到了 `/home/arduino/docker-data`）。

## 三、部署（有网）

### 方式 A：官方导入（最省事）

```bash
scp "uno-q-ros2-demo_20261124.app.zip" arduino@<板子IP>:~/
ssh arduino@<板子IP>
arduino-app-cli app import ~/uno-q-ros2-demo_20261124.app.zip
# 导入后会打印落地目录，一般是 ~/ArduinoApps/uno-q-ros-2
cd ~/ArduinoApps/uno-q-ros-2       # 换成上一步打印的路径
bash deploy/prepare.sh             # 拉 3 个镜像 + 构建 ros2_bridge，首次 10~15 分钟
arduino-app-cli app start "$PWD"
```

### 方式 B：直接拷源码目录

```bash
# 1. 把整个 uno-q-ros2-demo_20261124 目录放到 ~/ArduinoApps/ 下
#    （目录名随意，但建议保持 uno-q-ros2-demo）
scp -r uno-q-ros2-demo_20261124 arduino@<板子IP>:~/ArduinoApps/uno-q-ros2-demo

# 2. 准备镜像（同上，约 10~15 分钟）
cd ~/ArduinoApps/uno-q-ros2-demo
bash deploy/prepare.sh

# 3. 启动（App Lab 会编译并烧录固件、生成 compose、起三个容器）
arduino-app-cli app start ~/ArduinoApps/uno-q-ros2-demo
```

两种方式等价，落地目录名不同而已。打开 `http://<板子IP>:7000` 就是操作页面。

**为什么要用 `app start`**：它负责编译烧录 MCU 固件、生成
`.cache/app-compose.yaml`（其中把 `/dev`、`/dev/input`、pipewire、地图目录
挂进容器）、按 `bricks:` 起官方 brick。直接 `docker compose up` 会缺这些，
表现为"页面能开但没画面/没遥测"。

## 四、部署（无网 / 车间现场）

在**有网**的机器上（可以就是同一块板子，先联网跑一遍）：

```bash
bash deploy/save_images.sh          # 生成 deploy/images/*.tar，约 5.5 GB
# 或者加 --gzip，约 2.5 GB，A53 上要十几分钟
```

把这几个 tar 拷到目标板的 `deploy/images/`，然后：

```bash
bash deploy/load_images.sh          # docker load，名字与 compose 一致，不用 retag
bash deploy/prepare.sh --offline --skip-build
arduino-app-cli app start ~/ArduinoApps/uno-q-ros2-demo
```

> 固件平台仍需联网一次（App Lab 会按 `sketch.yaml` 把
> `arduino:zephyr 1.1.0` 装到 `~/.arduino15/internal/`）。如果目标板也完全
> 没网，需要提前把 `~/.arduino15/internal/arduino_zephyr_1.1.0_*` 和
> `~/Arduino/libraries` 一起拷过去。

## 五、只换代码（板子已经在跑这套系统）

只改网页/ROS 节点/固件时，不需要重新准备镜像：

```bash
# 改 python/ assets/ → 直接覆盖文件，重启 app 即可
# 改 bricks/ros2_bridge/**（ROS 节点、nav2.yaml）→ 必须重建镜像
cd ~/ArduinoApps/uno-q-ros2-demo/bricks/ros2_bridge && docker build -t ros2_bridge:local ./docker
# 改 sketch/** → app start 会自动重编重刷
arduino-app-cli app stop  ~/ArduinoApps/uno-q-ros2-demo
arduino-app-cli app start ~/ArduinoApps/uno-q-ros2-demo
```

## 六、依赖清单（脚本会自动准备）

| 名称 | 用途 | 来源 |
|---|---|---|
| `ghcr.io/arduino/app-bricks/python-apps-base:0.12.0` | 主容器（含 Python 3.13 / OpenCV 4.13 / numpy） | ghcr → 南大镜像 |
| `ghcr.io/arduino/app-bricks/ei-models-runner:0.12.1` | 物品检测推理（yolo-x-nano，**模型在镜像内**） | ghcr → 南大镜像 |
| `ros:jazzy-ros-base-noble` | 构建 `ros2_bridge:local` 的基础镜像 | Docker Hub → daocloud / 1ms |
| `ros2_bridge:local` | ROS 2 栈（rosbridge + Nav2 + 定位 + 仲裁） | 本机 `docker build` |
| `arduino:zephyr 1.1.0` + RouterBridge 0.4.4 / RPClite 0.3.1 / MsgPack 0.4.2 / Arx* / DebugLog | MCU 固件 | App Lab 按 `sketch.yaml` 安装 |

检测模型不需要单独下载：`yolo-x-nano.eim`（18 MB）和另外 9 个 `.eim`
都在 `ei-models-runner` 镜像的 `/models/ootb/ei/` 里。

## 七、启动后验收清单

| 检查 | 期望 | 不满足时看 |
|---|---|---|
| 页面 `:7000` | 能打开，顶部"ROS 2 已连接 / 实时已连接" | `docker logs uno-q-ros2-demo-main-1` |
| MCU 状态 | `MCU 空闲`、电压 ≈ 电池电压、`nFAULT 正常` | USB/串口线、固件是否烧录（`reason` 应显示上电） |
| 摄像头 | 有画面、360×640 竖屏、≈14 fps | `/api/camera/status` 的 `error`；`/dev/video0` |
| 物品检测 | 摄像头下方显示类别/置信度，`≈600 ms/帧` | `/api/detect` 的 `ready`/`error`；runner 容器是否 healthy |
| 雷达 | 地图上出现扫描点云 | `/scan` 频率（设计值 2~3 Hz） |
| 导航 | 设位姿→"定位已确认"→点目标能走 | 见下节 |

## 八、已知坑（都踩过）

1. **ghcr.io 直连拉不动**（IPv4 401/超时、IPv6 直接 000）。
   用 `ghcr.nju.edu.cn` 拉下来再 `docker tag` 成原名 —— `prepare.sh` 已内置，
   也支持用 `GHCR_MIRROR=... bash deploy/prepare.sh` 换源。
2. **Docker Hub 拉 `ros:jazzy-ros-base-noble` 慢/断**。
   脚本依次试 `docker.m.daocloud.io`、`docker.1ms.run`，再试官方源。
3. **固件平台版本不能将就**。`sketch.yaml` 钉的是 1.1.0 + RouterBridge 0.4.4
   + RPClite 0.3.1；板上一旦落到 1.0.0 / 0.4.3 / 0.3.0，能编译、能烧录，
   但**不会向 arduino-router 注册任何 RPC**，表现为网页遥测全空、
   `ros_status` 报 "method not available"。
4. **rosbridge 不是 8765**。compose 映射的 8765 是 foxglove bridge；
   rosbridge 在容器内 9090 且没发布到主机。要在外部看 ROS 话题，走
   SSH 端口转发到容器 IP，别指望 `ws://<板子IP>:9090`。
5. **内存只有 3.6 GB**，ros2 容器占 2.4 GB。在板上临时开 8 个 `ros2` CLI
   节点会把可用内存压到几十 MB，内核会先杀导航栈（容器全部 Exited 137），
   看起来像"应用自己崩了"。排查请用 rosbridge，别叠进程。
6. **导航的两个已知限制**（与移植无关，但现场会遇到）：
   - 初始位姿点必须落在地图白色可通行区，点进灰格/黑格时规划器会报
     `Failed to create plan with tolerance of: 0.15`，然后跑 25 s 恢复动作再失败；
   - 位姿重置后 AMCL 会跳几厘米、静止时偏航有 0.17°/s 漂移，属正常。

## 九、开机自启（演示必做）

板子掉电重启后 App **不会**自己起来（`arduino-app-cli` 没有 autostart 命令），
表现是网页打不开、手柄完全没反应，必须有人手动 `app start`。现场最常见的原因
是电池电压低时电机启动电流把整机拉复位——重启后又不会自启，看起来就像"机器人死了"。

`deploy/system/unoq-robot-app.service` 是配套的 systemd 单元：

```bash
sudo cp deploy/system/unoq-robot-app.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable unoq-robot-app.service
# 应用没在跑时可以手动验证一次：
sudo systemctl start unoq-robot-app.service
```

单元里已经处理了两件容易踩的事：`After=docker.service arduino-app-cli.service
user@1000.service`（否则 `/run/user/1000/pipewire-0` 还不存在，compose 的 bind
mount 会挂到空目录上），以及 `User=arduino`（root 执行会把 App 目录写成 root 所有）。

## 十、这个 `deploy/` 目录要不要留

留着方便下次换板；不需要就 `rm -rf deploy`，不影响 App 运行（App Lab 只读
`app.yaml` / `sketch/` / `python/` / `assets/` / `bricks/`）。
